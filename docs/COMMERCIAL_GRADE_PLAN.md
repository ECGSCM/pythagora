# Phase 7 — Commercial Grade Plan(安定性・滑らかさの商用水準化)

**作成: Fable 5 / 2026-07-03** — 症状:「モジュールが出現しない」「高負荷で固まる」

## 診断(コード確認済みの根本原因)

### 固まる(Freeze)
1. **[主犯] リバーブIRの実行時再生成** — `AudioBus` が衝突量に応じ decay を 2〜20s で連続変化させ、0.25s ずれるたびに `Tone.Reverb` が**最長20秒のインパルス応答をオフラインレンダリング**。コンボ中は繰り返し発生し、メインスレッドを数百ms〜秒単位でブロック。
2. **[副犯] 物理ワーカーのキャッチアップスパイラル** — `maxSubSteps` 未指定。フレーム落ち→サブステップ増→さらにフレーム落ちの悪循環。
3. **[副犯] 衝突ごとの Tone ノードグラフ新規生成**(6〜20ノード/hit)→ GC 停止。ボイス上限はあるが生成/破棄の churn 自体が残る。
4. moduleHits Record のセッション内無限成長(軽微)。

### モジュールが出現しない
1. **選択レース** — キー選択→即クリックで旧 selectedNodeType が使われる(React commit 前に r3f イベントが旧 props を読む。検証済み)。
2. **クランプ遠方配置** — 視界端クリックが ±16/0..24 に丸められ、クリック地点から遠く離れて出現=「出現しない」ように見える。
3. **プレーン外クリックは無反応**(フィードバックゼロ)。
4. ワーカー飽和時、新規 static body の初期транスフォーム同期が遅延。

## 対策(サブフェーズ)

### 7A 音響の産業強度化(Opus)
- **リバーブIR固定**: decay をロード時1回生成の固定値(10s)にし、動的表現は send ゲインのみで行う(IR再生成を完全廃止)
- **真のボイスプーリング**: 楽器ごとに固定数のグラフを事前構築し、再トリガー方式に(生成/破棄 churn 廃止)。既存の音色レシピ・velocityGain/brightness API は維持
- **音響イベント予算**: 100ms 窓あたりのトリガー上限(超過分は最も静かなものを間引き)

### 7B 物理の安定化(Fable — 即時実施)
- `maxSubSteps={3}` + stepSize 明示(キャッチアップ上限)

### 7C 配置UXの確実化(Sonnet)
- **ゴーストプレビュー**: 選択モジュールの半透明プレビューがポインタに追従(クランプ後の実配置位置に表示 — 「どこに出るか」が常に見える)
- **選択レース根絶**: Scene がクリック時に store/ref から選択を読む(props 経由の凍結値を廃止)
- プレーン外クリック時はプレビュー非表示=置けないことが視覚で分かる
- moduleHits を Clear All / ノード削除時に掃除

### 7D 適応品質(Sonnet)
- drei `PerformanceMonitor` で実測FPSに応じ: dpr 段階降格 → Noise 停止 → Bloom 半減/停止
- 低性能検出時 spawnCap を 6 に自動縮小

### 7E ストレス検証・リリース(Fable)
- 検証プロトコル: 60秒間に30マーブル+モジュール15個+コンボ嵐でフレーム時間 p95 とフリーズ(>500ms 停止)ゼロを確認
- 修正後に main / gh-pages へデプロイ

## 受け入れ基準(商用水準)
- 高負荷60秒テストで 500ms 超のメインスレッド停止 **0回**
- 配置操作の成功率100%(クリック=プレビュー位置に必ず出現)
- 全ゲート(lint/tsc/test/build)+ 既存49テスト維持
